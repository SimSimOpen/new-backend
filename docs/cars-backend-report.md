## Что сделано

### Модель данных
- `Car` → таблица `cars`, фото → `car_images`. Таблицы создаёт Hibernate (`ddl-auto=update`).
- Поля автомобиля:
  - марка, модель (пока текстом, справочник добавим позже);
  - год, пробег, объём двигателя, цвет, растаможен;
  - кузов, топливо, коробка, привод, состояние (enum-ы в `common/.../enums/car`).
- Общие поля, как у недвижимости: цена, `OfferType`, `ListingStatus`, `OccupancyStatus`, контакт, агент, просмотры.
- Локация хранится прямо в строке `cars`: `region_id`, `district_id`, `place_id`, адрес, координаты. В ответе приходит `location: [регион, район, махалля, адрес]` на языке запроса, в том же формате, что у недвижимости.

### API `/api/product/v1/car`
| Метод | Путь | Доступ |
|---|---|---|
| POST | `create-draft` | агент/админ |
| PUT | `update/{id}` | владелец/админ, частичное обновление (null = не менять) |
| GET | `{id}` | ACTIVE видят все авторизованные; черновик/архив видят только владелец и админ |
| DELETE | `{id}` | владелец/админ (фото удаляются и из хранилища) |
| DELETE | `delete/image/{id}` | владелец/админ; если удалили обложку, ей становится следующее фото |
| GET | `car-media-count/{id}` | как `GET {id}` |
| GET | `agents-all` | агент получает свои машины, админ все |
| GET | `stats` | всего / активно / продано / черновики |
| GET | `filter` | **публичный** |
| POST | `{id}/views` | **публичный** |

Параметры фильтра: `search` (заголовок, описание, марка, модель), `brand`, `model`, `offerType`, `occupancyStatus`, `condition`, `bodyTypes[]`, `fuelTypes[]`, `transmissions[]`, `driveTypes[]`, `regionId`, `districtId`, `placeId`, `priceFrom/To`, `yearFrom/To`, `mileageTo`, сортировка через `sort=price,asc` и т.п.

### Фото
- `POST /api/media/v1/upload-car-media?car_id=` (без `car_id` создаётся черновик). Используется тот же конвейер, что у недвижимости: webp и водяной знак. Файлы кладутся в `real-estate-media/cars/{id}/images/`.
- Общий код загрузки вынесен в `uploadListingMedia`, загрузка фото недвижимости работает как раньше (проверено).

### Категория
- `CarsListingCounter`: на главной показывается реальное число активных машин.
- В `marketplace-categories.json` у `cars` стоит `available: true`.
- ⚠️ **На проде** сидер не обновляет существующие строки, поэтому один раз нужно выполнить:
  ```sql
  UPDATE marketplace_categories SET available = true WHERE slug = 'cars';
  ```

## Закрытые дыры безопасности (в коде машин)

1. **Публичный фильтр отдавал бы черновики.** Аноним и клиент всегда получают только `ACTIVE`, что бы ни передали в `listingStatus`. Агент видит только свои машины в любом статусе, админ видит все.
2. **Изменение и удаление чужого объявления.** `update`, `DELETE`, удаление фото разрешены только владельцу или админу.
3. **Загрузка фото в чужую машину по `car_id`.** Права проверяются синхронно при запросе, до постановки в async-загрузку: в фоне `UserContext` пустой.
4. **Чтение чужих черновиков** через `GET /car/{id}` и `car-media-count`. Черновик/архив отдаётся только владельцу или админу, остальным приходит «не найдено».

## Как проверено

Backend запускался локально на временных Postgres, Redis и S3-хранилище. Проверено вживую:

- черновик → заполнение → частичное обновление (остальные поля сохраняются);
- фильтры без токена и с токеном; аноним с `listingStatus=DRAFT` всё равно получает только ACTIVE;
- поиск, статистика, просмотры, 401 без токена, удаление;
- загрузка фото: файл реально появляется в хранилище (`200 image/webp`); при удалении обложки обложкой становится следующее фото;
- второй агент (отдельный токен) на чужой машине: чтение черновика, media-count, изменение, удаление и загрузка фото возвращают отказ, фото не добавилось; после публикации машину видно; в фильтре он видит 0 чужих.

Ограничение: ошибки прав возвращаются со статусом **400** (так в проекте работает `UserException`), а не 403.
